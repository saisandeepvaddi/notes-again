# Notes Again mobile

Expo SDK 57 app (React Native 0.86, Expo Router, TanStack Query, Zod 4). Its own pnpm root. The repo-root [AGENTS.md](../AGENTS.md) conventions apply here too (no code comments; run formatters only on files you touch).

## Expo changes every SDK

Don't trust remembered Expo or React Native APIs. Check the `expo` major in `package.json` and read the versioned docs (`https://docs.expo.dev/versions/v57.0.0/`). The installed `.d.ts` files are the final word. Add dependencies with `npx expo install <pkg>`, not `pnpm add`, so versions match the SDK.

## Layout

- `src/app/`: routes only. `connect` shows when there's no stored connection, `(app)` when there is (`Stack.Protected` in `src/app/_layout.tsx`). `(app)/(tabs)` holds the native tabs. Today and Notes share one stack layout through the `(index,notes)` group. Note detail, review and new note sit on the `(app)` stack so they cover the tab bar.
- `src/screens/`: screen bodies the routes render.
- `src/api/`: `client.ts` (fetch + Zod parsing, bearer token, 401 → back to Connect, falls back to a connection's `fallbackUrl` when the server can't be reached), `connection-store.ts` (SecureStore), `connect.ts` (server probe and sign-in), `notes.ts` (note query hooks), `library.ts` (trash, projects and tags, bulk actions, settings, import/export). Query keys use the web app's families (`["notes"]`, `["due-notes"]`, `["trashed-notes"]`, `["projects"]`, `["tags"]`).
- Screens on the `(app)` stack beyond notes and review: `trash`, `organize` (projects & tags), `transfer` (import & export), all reached from Settings. Row actions use `ActionMenu` (`@expo/ui/community/menu`, a native menu on both platforms) because Android's `Alert` shows at most three buttons; keep `Alert` for confirmations.
- `src/components/note-markdown.tsx` is an Expo DOM component (`"use dom"`): note bodies render in a webview with the same `markdown-exit` + Shiki setup and `.markdown-content` styles as the web app's `NoteContent`. It reports its height back through `onHeight`, because `matchContents` collapses inside a ScrollView.
- `src/components/rich-editor/` is the note editor, the same MDXEditor setup as the web app's `MarkdownEditor`, running in an Expo DOM component. Note detail edits in place and autosaves (`use-note-autosave.ts`, 800 ms like the web app); new notes use it with an explicit Save. The native keyboard toolbar drives the editor through `useDOMImperativeHandle`, and the DOM side reports format state, focus, caret and height back. `EditorBridge` holds the native refs (React Compiler rejects refs passed around in plain objects). `lexical` and `@lexical/link` are pinned to the version MDXEditor resolves; a second copy breaks editor commands. Keyboard tracking comes from `react-native-keyboard-controller` (`KeyboardProvider` wraps the root layout).
- `src/theme.ts`: the web app's tokens (DESIGN.md) as hex values for light and dark.

## On-device server

`modules/notes-core` is a local Expo module that links the Rust `notes-again-server` crate (`modules/notes-core/rust`, a `staticlib`/`cdylib` with a C ABI for iOS and JNI exports for Android). The native side starts it in desktop mode on `127.0.0.1` as early as it can (an `ExpoAppDelegateSubscriber` at `didFinishLaunching` on iOS, module creation on Android) with a per-launch secret generated natively, and `src/api/local-server.ts` asks for its port and secret, and `connection.tsx` keeps a `local` connection whose token is that secret (the server accepts it as a bearer token). Everything the screens do goes through that local server, so the phone has the desktop's database, scheduling and sync code. Sync settings use the desktop endpoints (`/api/sync/*`, `src/api/sync.ts`). When the app comes back to the foreground it checks `/healthz`, restarts the server if iOS dropped it, and syncs; going to the background also syncs so offline edits are pushed before iOS suspends the app.

- Build the library before a native build: `modules/notes-core/scripts/build-ios.sh` (XCFramework with device and arm64/x86_64 simulator slices, gitignored; rerun `pod install` after it changes slices) or `build-android.sh` (`jniLibs`, needs `cargo-ndk` and the NDK). `.github/workflows/mobile-native.yml` builds both.
- `ios/` and `android/` are generated by `npx expo prebuild` and not committed.
- `requireOptionalNativeModule` keeps Expo Go working: without the module the app uses the old remote connection flow (`connect`, `scan`).

## Sharing code with the web app

`@web/*` maps to `../frontend/src/*`. Import only pure modules from it. `metro.config.js` resolves bare imports in those files (like `zod`) from `mobile/node_modules`, and `tsconfig.json` maps `zod` to the app's copy so types line up. A shared file that picks up a `@/` import or a web-only package breaks the mobile bundle.

## Design

Follow [DESIGN.md](../DESIGN.md), sized for touch: 44pt minimum targets, 15–17pt body text, Geist for chrome and headings, Geist Mono for code, and the reading font for note titles and note bodies, green only for action, selection and focus, flat cards with hairline borders, pill badges for difficulty, rating and tags. The reading font is a per-device choice in Settings (`useReadingFont`, Geist or Literata): text that shows note content takes `<AppText reading>`, title inputs use `family.semibold`, and the DOM markdown and editor components get it as the `font` prop.

## Known platform quirks

- iOS 26: setting `headerStyle.backgroundColor` hides large titles. The header picks up the paper color from the navigation theme instead.
- `<Link asChild>` drops a `Pressable`'s function `style`, so rows navigate with `router.push`.

## Verify

`pnpm typecheck`, `pnpm lint`, and `npx expo-doctor` after dependency or `app.json` changes (pnpm 12's own `pnpm doctor` shadows the script). Run the app against a throwaway backend (`DB_PATH=/tmp/x.db ADMIN_PASSWORD=… cargo run --manifest-path server/Cargo.toml -- serve --host 0.0.0.0 --port 8300`) and check the screen you changed in a simulator.
